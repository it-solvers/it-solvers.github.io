## 문서 규칙

- 파일 이름은 `docs/spec-vX.XX.md`다. 이 문서를 새로 쓸 때마다 버전을 **0.01씩 올린 새 파일**을 만든다(v0.90 → v0.91 → v0.92 …). 이전 버전 파일은 지우지 않는다. 가장 높은 번호가 최신이다.
- 이 저장소는 그대로 사이트로 공개된다. `docs/`의 내용도 `https://itsolvers.co.kr/docs/...`로 열린다. **계정 ID, 비밀번호, 개인 연락처, 인증 정보는 쓰지 않는다.**
- 이 문서는 현재 상태를 기록한다. Claude가 따라야 하는 작업 규칙은 저장소 루트의 `CLAUDE.md`가 우선한다.

## 1. 개요

- 사이트: 아이티해결단(IT Solvers) 소개 사이트. 서비스 소개, 기술 인사이트(직접 만든 도구와 업무 지식), 주요실적, 문의로 구성한다.
- 기술: 정적 HTML, CSS, 약간의 JavaScript. 서버와 DB는 없다.
- 언어: 한국어가 기본이고 영문 페이지(`en/`)가 별도로 있다.
- 문의: 메인 페이지의 문의 섹션에서 이메일(`mailto:`)로 받는다.

## 3. 배포와 운영

| 항목 | 현재 방식 |
|---|---|
| 소스 저장소 | GitHub `it-solvers/it-solvers.github.io` (브랜치 `main`) |
| 게시 | GitHub Pages. `main`에 푸시하면 1~2분 안에 반영된다. |
| 도메인 | 가비아에 등록. 네임서버도 가비아(`ns.gabia.co.kr` 등), DNS A 레코드 4개(185.199.108~111.153)와 `www` CNAME이 GitHub Pages를 가리킨다. |
| HTTPS | GitHub Pages 기본 인증서 |
| 로컬 확인 | Docker nginx(`web/docker-compose.yml`)가 이 폴더를 읽기 전용으로 연결해 `http://localhost/`로 보여 준다. 파일을 고치면 바로 반영된다. |
| 커밋과 푸시 | 작업이 끝나면 Claude가 자동으로 **커밋**하고, **푸시는 사용자가 직접** 한다. |
| 안전잠금 | 도메인 안전잠금(On)을 유지한다. 네임서버를 바꿀 때만 풀고 다시 건다. |

### 이력
- 2026-10-18: AWS(Amplify, Route 53)로 호스팅을 옮겨 보았으나 설정이 복잡해 **같은 날 GitHub Pages로 원복**했고 AWS 계정도 해지 요청했다. 현재 AWS는 쓰지 않는다.
- 같은 날 도메인의 메일 관련 DNS 레코드(MX, SPF 등)를 삭제했다. 도메인 메일(`@itsolvers.co.kr`)은 쓰지 않는다.

## 4. 메인 페이지 구조 (`index.html`)

### 4.1 섹션 순서
`HERO(+새소식)` → `#services` → `#about` → `#process` → `#insights` → `#history` → `#contact`

### 4.2 상단 메뉴
`English` · `서비스` · `아이티해결단` · `진행순서` · **`기술 인사이트 ▾`**(하위: `MVP` · `계산도구` · `업무지식`) · `주요실적` · `문의`
- 하위 메뉴는 마우스를 올리면 열리고, 키보드 이동 시에도 열린다. 터치 화면(801px 이상)은 눌러서 열고 닫는다. 800px 이하(햄버거 메뉴)에서는 항상 펼쳐서 들여쓰기로 보인다.
- 항목을 고르면 메뉴가 닫히고, 이동한 제목이 고정 헤더에 가려지지 않도록 여백을 둔다.
- 801~1000px에서는 메뉴 간격을 줄이고 글자가 꺾이지 않게 한다.
- 헤더는 어두운 화면 모드에서도 항상 흰색이다. 테마 버튼(☀/☾)으로 밝은/어두운 화면을 전환한다.

### 4.3 서비스 (`#services`) 카드 3개
1. **AI 중심 소프트웨어 · 앱 개발** — 분석·설계·구현·시험 전 과정에 AI를 활용해 먼저 작동하는 제품(MVP)을 만들고 다듬는다. 금융·리스 업무 이해 기반 설계 검토 포함.
2. **IT자산 공급**
3. **컴퓨터 · 서버 · NAS 구축**

### 4.4 새소식 (히어로 영역)
- **항상 최신 3개만** 유지한다. 새 항목을 맨 앞에 넣으면 가장 오래된 항목을 뺀다(빠진 항목의 카드나 본문은 그대로 둔다).
- 태그: MVP 항목은 `MVP`, 그 외 인사이트는 `기술 인사이트`, 실적은 `주요실적`.
- 현재 3개: 전자계약서, 리스 견적 내기, 개발자를 위한 회계 (모두 `MVP`).

### 4.5 기술 인사이트 (`#insights`) — 한 섹션 안에 3개 그룹
본문 순서와 상단 하위 메뉴 순서는 항상 같다: **MVP → 계산도구 → 업무지식**.

| 그룹 (id) | 카드 | 연결 |
|---|---|---|
| MVP (Minimum Viable Product, 최소 기능 제품) `insights-mvp` | 전자계약서 | `insights/e-contract.html` |
| | 리스 견적 내기 | 외부(Vercel) — 개발 중 |
| | 개발자를 위한 회계 | 외부(Vercel) — 회계 퀴즈 |
| 계산도구 `insights-tools` | 리스 현금흐름 기준 IRR 계산기 | `insights/lease-cashflow-irr-calculator.html` |
| | 목표 IRR 기준 금리 역산 계산기 | `insights/irr-to-rate-calculator.html` |
| | 리스료 계산기 | `insights/lease-payment-calculator.html` |
| 업무지식 `insights-knowledge` | 리스 용어 정리 | `insights/lease-terms.html` |
| | 리스 개요 | `insights/lease-overview.html` |

- 외부 링크와 새 탭으로 열리는 링크는 `target="_blank" rel="noopener"`이고 카드 제목 끝에 `↗`가 붙는다.
- 진행 중인 항목은 제목에 `(진행중)`을 붙이는 규칙이 있다.

## 5. 푸터와 저작권

- 푸터에는 상호, 대표, 사업자등록번호 같은 회사 정보만 둔다. 인사이트나 새소식에 있는 링크를 푸터에 중복해서 두지 않는다.
- 모든 페이지 푸터 맨 아래에 저작권 문구를 둔다: 한글 `© 2026 아이티해결단 (IT Solvers). All rights reserved.`, 영문 `© 2026 IT Solvers. All rights reserved.` (연도는 고정값 2026).

## 6. 인사이트 페이지 (`insights/`)

| 페이지 | 설명 |
|---|---|
| `e-contract.html` | 전자계약서 소개(7장) |
| `lease-overview.html` | 리스 개요(K-IFRS 제1116호) |
| `lease-terms.html` | 리스 용어 정리 |

- 각 페이지 `<head>`는 같은 형식이다: 구글 태그, 애드센스, title, description, robots, canonical, hreflang, 파비콘, OG, 트위터 카드, JSON-LD.

- 영문판(`en/insights/`)은 리스 5종만 있다. 전자계약서와 MVP 구성은 영문에 반영하지 않았다.

## 7. 전자계약서 소개 페이지 (`insights/e-contract.html`)

- 성격: 앱과 분리된 정적 소개 페이지. 보는 사람은 계약서를 보내는 "공급인"이다.
- 첫 화면 제목: "계약은 가끔인데, 전자계약서 구독료는 매달 내야 하나요?"
- 구성: 첫 화면 → 이렇게 씁니다(4단계) → **실제 화면 6장** → 좋은 점 → 이런 분께 → 알아 두실 점 → 요금 → 시험 사용 신청 → 다음에 해볼 만한 것(5개).
- **시험 사용 신청**은 `mailto:`로 받는다(제목과 "계약 건수 / 하시는 일 / 연락처" 양식이 채워진 메일 창).
- 실제 화면 이미지(`insights/e-contract/01~06-*.webp`)는 시험용 데이터로 찍었다. **상대방 이름과 로그인 이름은 가렸고, 휴대폰 번호가 보이는 화면은 쓰지 않는다.** 새 화면을 넣을 때도 같은 원칙을 지킨다.
- 본문 문구 원칙: 요금 숫자는 확정 전이라 넣지 않고, 법적 효력은 전문가 검토 전이라 단정하지 않는다.
- 검색에 공개한다(`robots: index, follow`).

## 8. 검색(SEO)과 분석

- 모든 페이지: `title`, `description`, `canonical`, `robots(index, follow)`, OG와 트위터 카드, JSON-LD.
- 메인 페이지는 `hreflang`으로 한글/영문을 연결한다. 영문이 없는 인사이트(전자계약서)는 `ko`와 `x-default`만 둔다.
- `sitemap.xml`: 현재 URL 13개(메인, 영문 메인, 한글·영문 인사이트, 전자계약서). 새 공개 페이지를 만들면 추가하고 수정일을 갱신한다.
- `robots.txt`: 전체 허용, 사이트맵 위치 명시.
- 분석과 광고: 구글 애널리틱스 `G-SBGBVC3WB8`, 애드센스 게시자 `ca-pub-5463289214022004` 스크립트가 모든 페이지에 들어 있다. 광고 단위(`<ins class="adsbygoogle">`)는 따로 넣지 않았다.
- 소유 확인: 구글(메타 태그와 HTML 파일), 네이버(메타 태그).
- 새 페이지를 공개한 뒤에는 Search Console에서 URL 검사 → 색인 생성 요청을 한다.

## 9. 영문 페이지 정책

- `en/index.html`과 `en/insights/`는 **사용자가 따로 요청할 때만** 만들거나 반영한다.
- 영문 메인에는 아직 MVP 그룹, 하위 메뉴, 전자계약서, AI 중심 개발 문구가 반영되어 있지 않다.

## 10. 알려진 한계와 미결

- 검색용 문구(`<title>`, meta description, JSON-LD의 서비스 이름)는 아직 "소프트웨어·웹·앱 개발"이며 "AI 중심"을 반영하지 않았다.
- 상단 메뉴와 새소식 태그의 "MVP"는 약자만 쓴다(그룹 제목에만 풀 스펠링).
- `index.html`에는 열린 `<div>`가 닫힌 `<div>`보다 1개 많은 상태가 이전부터 있다(렌더링에는 문제가 없어 보이며 원인은 확인하지 않았다).
- 애드센스는 스크립트만 있고 광고 단위가 없다. 광고가 실제로 보이는지는 애드센스 설정에 달려 있다.
- 전자계약서의 요금과 법적 효력 관련 문구는 확정 전이다.
