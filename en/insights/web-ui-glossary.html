Web UI Glossary

Each term gets one card with a key-syntax table, a live example you can click, and code you can copy. Use the search box above whenever you need to find something, in Korean or English.

This page is a glossary for reference while developing. The small examples are for understanding the names, looks, and working principles of screen elements. Adjust them to your needs, and run accessibility checks and device testing before using them in a real service.

Revision history
    Common terms
    UI
    User Interface, the screen layout that people look at and press
    HTML
    HyperText Markup Language, the language that describes the structure of a page
    CSS
    Cascading Style Sheets, the language that sets the look and layout of a page
    JavaScript
    JavaScript, the language that adds behavior to a page
    SVG
    Scalable Vector Graphics, a vector image format that stays sharp when enlarged
    Canvas
    Canvas, an area where JavaScript draws dots and shapes directly
    ARIA
    Accessible Rich Internet Applications, attributes that tell assistive technology such as screen readers about roles and states
    FPS
    Frames Per Second, how many times the screen updates in one second
    CDN
    Content Delivery Network, a distribution network that lets library files download quickly
    How to use the code (please read this first if you are new)
    1. Save
    Open a card’s “Save the code” section and press the Save as file button. A file named name.html is saved. (You can also copy the code and paste it into a file yourself.)
    Making it yourself
    Paste the code into an empty file and save it as name.html. A code editor (for example, VS Code) is the safest choice.
    Mac
    In TextEdit, first choose the menu item Format → Make Plain Text (Shift+Command+T), then paste and save. Otherwise the code appears on screen as literal text.
    Windows
    In Notepad, when saving, set the file type to “All files,” set the encoding to UTF-8, and add .html to the end of the name. Make sure the name has not turned into .html.txt.
    2. Open
    Double-click the saved file to open it in a browser (such as Chrome).

    Sources checked and parts that still need verification (first checked October 29, 2026 · cards added November 2, 2026)

    Reference browser: Chrome — Every example on this page was built to work in Chrome and was opened and checked directly. The browser version numbers below are for reference if you also target Safari or Firefox; if you only use Chrome, there are no features you cannot use. (Latest Chrome version)

    • Browser support (verified): backdrop-filter is supported from Chrome 76, Edge 79, Firefox 103, and Safari 18, and has been at the newly available stage of Baseline (a web standards indicator that a feature works in all major browsers) since September 16, 2024. Container queries are supported from Chrome and Edge 105, Firefox 110, and Safari 16, and have been at the widely available stage since August 14, 2025. CSS linear() is supported from Chrome and Edge 113, Firefox 112, and Safari 17.2. Intl.Segmenter is supported from Chrome and Edge 87, Safari 14.1, and Firefox 125. Source: the Web Features Explorer page on backdrop-filter, container queries, linear(), Intl.Segmenter .
    • offset-path (motion path) is supported from Chrome 46, Edge 79, Firefox 72, and Safari 16 according to caniuse (caniuse). However, detailed support for the path() function form is not in the sources and needs verification.
    • View Transitions (the page transition feature) within the same page are supported from Chrome and Edge 111, Safari 18, and Firefox 144 (Chrome for Developers). Cross-page navigation transitions were shipped by Chrome in 2024 and Safari is said to support them too, but Firefox’s status and exact versions are not in the sources. The name attribute of details is supported from Chrome and Edge 120, Firefox 130, and Safari 17.2 (Chrome for Developers). Scroll-driven animations are supported from Chrome and Edge 115 and Safari 26, and Firefox is listed as a technology preview (Chrome for Developers). MDN lists it as limited availability, so whether Firefox officially supports it needs verification (MDN).
    • Libraries and tools: the latest version of flubber, 0.4.2, dates from March 2018 and is classified as inactive in the Snyk assessment (Snyk). The latest canvas-confetti on jsDelivr is 1.9.4 (jsDelivr). However, we could not confirm whether it is listed on cdnjs or what the actual file path is. cubic-bezier.com is a tool introduced in Lea Verou’s 2011 post, and we could not confirm whether it is currently reachable.
    • Timing reference: the Material Design 1 documentation suggests 150–200 ms on desktop, about 300 ms on mobile, 375 ms for large, complex full-screen transitions, 225 ms for entering elements, and 195 ms for exiting elements (m1.material.io). Other timing figures (stagger of 60–100 ms, microinteractions of 0.1–0.4 seconds, and so on) are rules of thumb with no source.
    • Toast and Snackbar: the mdui documentation, which carries over Material Design 1 (the first generation of Google’s design guidelines), treats them as different components. A snackbar reports the result of an action and can have one button, while a toast is for Android system messages and has no interaction. We correct our earlier explanation that grouped them as the same thing. This source is a re-published document rather than the original, and terminology differs between web libraries, so this needs verification.
    • 51 cards added on November 2, 2026 (screen structure · navigation · state/forms · rendering/layout · interaction · performance): We could not reach MDN, the React documentation, or the Web Features Explorer, so this time we could not cross-check the facts against the original sources. For that reason, browser version numbers are not included, and the behavior was verified by opening and clicking through it in Chrome (Chromium). We could not verify actual touch, vibration, or safe-area values on mobile devices.
    • Especially needs verification: the detailed rules of React ErrorBoundary and controlled/uncontrolled components, the exact behavior of SWR (a library with the same name as the HTTP cache extension RFC 5861), iOS and desktop support and user-gesture requirements for haptics (navigator.vibrate), interpolate-size for accordions, conflicts between pull-to-refresh and default browser behavior, and numbers such as hover-intent timing (rules of thumb).
    • 6 Data Grid cards added on 2026-11-03: Because this site has no server, the queries, progress, and errors are demos imitated with fake data and timers. Real server integration, large data sets (virtual scrolling), and table navigation with screen readers need verification.
    • The code is shortened to aid understanding. Accessibility checks and per-device testing still need to be done separately before using it in a real service.
